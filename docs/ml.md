# ML- и LLM-часть системы

## 1. Какая задача чем решается

| Задача | Подход | Почему |
|---|---|---|
| Критичные запреты, VIP/SLA, известный incident code | правила | поведение должно быть однозначным и аудируемым |
| Тема, очередь, приоритет, risk flags | классическая ML / компактный encoder | быстро, дёшево, можно калибровать confidence |
| Похожие тикеты и массовый инцидент | embeddings + clustering | формулировки различаются, но смысл одинаков |
| Поиск инструкции | hybrid retrieval + reranker | ответ должен опираться на актуальный источник |
| Формирование понятного ответа | шаблон, затем local GLM + RAG | LLM полезна для переформулирования, но не как источник фактов |
| Неудача локальной генерации | внешний LLM fallback | повышает доступность, но ограничен privacy и бюджетом |

LLM **не используется** на горячем пути классификации, для принятия решений о
возврате денег/доступе к аккаунту и без найденного достоверного источника. Она
также не закрывает high-risk тикет без оператора.

## 2. Какие модели и откуда

### Router

Первый baseline — `TF-IDF + Logistic Regression`: быстро обучается на внутренних
размеченных тикетах и показывает, насколько сложная модель вообще нужна.
Production-кандидат — открытый русскоязычный или multilingual encoder,
дообученный внутри компании на задачу multi-label classification. Он не
обучается с нуля: берутся открытые веса, затем fine-tuning на своей taxonomy.

У модели несколько выходов: `intent`, `queue`, `priority`, `risk_flags`.
`intent` отделён от `queue`: при реорганизации поддержки меняется mapping, а не
семантическая taxonomy.

### Embeddings и retrieval

Стартовый baseline — BM25 keyword search. Затем добавляется открытая
sentence-embedding модель, проверенная на русском языке, и cross-encoder
reranker. Для маршрутизации индекс содержит обезличенные тикеты с финальной
очередью и результатом; для ответа — только утверждённые статьи базы знаний.

### Генерация

Используется открытая instruction-tuned модель семейства **GLM**, развёрнутая
локально. Конкретный размер и quantization выбираются нагрузочным и качественным
тестом. Вначале модель работает без fine-tuning, только с RAG. Позже возможен
LoRA/fine-tuning на проверенных парах «контекст → хороший ответ»; случайно
принятые ответы модели в обучение напрямую не возвращаются.

Перед использованием открытых весов отдельно проверяются лицензия, поддержка
русского языка, возможность локального inference и требования к GPU.

## 3. Данные и разметка

Нужны исторические тексты, финальная очередь после всех переводов, resolution
code, риск-категория, действия оператора, CSAT и reopen в течение 7 дней. PII
удаляется до создания датасета.

Процесс разметки:

1. Согласовать короткую иерархическую taxonomy и примеры на каждый класс.
2. Взять итоговые очереди как слабые labels, очистить ошибочные/переоткрытые
   кейсы и дедуплицировать массовые инциденты.
3. Для gold set два оператора независимо размечают intent и risk; разногласия
   решает эксперт. Особенно тщательно размечаются редкие high-risk случаи.
4. Делить train/test по времени и группировать по пользователю, диалогу и
   incident cluster, чтобы одинаковые тикеты не оказались с двух сторон.
5. Правки операторов считать кандидатами для следующего датасета, а не
   мгновенной истиной для online-обучения.

## 4. Baseline-план

1. **Без генерации:** правила + TF-IDF classifier + BM25 + подсказка статьи.
2. **Лучший routing:** fine-tuned encoder, calibrated confidence, embeddings для
   похожих тикетов и incident clustering.
3. **Agent assist:** local GLM + RAG готовит черновик, но всегда с проверкой.
4. **Ограниченный auto-send:** только шаблоны и 2–3 низкорисковые категории.
5. **Внешний fallback:** включается последним после privacy, cost и quality gates.

Каждый этап должен доказать пользу отдельно; так понятно, какой эффект дал ML,
retrieval или LLM.

## 5. Валидация

| Часть | Offline-метрики | Стартовый ориентир |
|---|---|---:|
| Router | macro-F1, accuracy маршрута, recall каждого risk-класса | route accuracy ≥ 92%, risk recall ≥ 98% |
| Confidence | ECE/Brier, precision при выбранном coverage | ECE ≤ 0,05 |
| Retrieval | Recall@5, nDCG@10, freshness | Recall@5 ≥ 90% на gold set |
| Incident detection | precision/recall кластера, time-to-detect | подтвердить на replay инцидентов |
| Generation | groundedness, citation precision, unsafe rate | 100% citations у автоответов, 0 critical unsafe на test suite |
| Serving | p50/p95/p99 latency, throughput, GPU memory | router p95 ≤ 500 мс end-to-end |

После offline-теста идут shadow mode, canary и A/B-тест. В онлайне смотрим
переводы между очередями, принятие/редактирование черновика, время оператора,
CSAT и reopen, а не только ML-метрики.

## 6. Низкая уверенность

Raw probability нельзя считать надёжной уверенностью: scores калибруются на
validation set, пороги задаются отдельно по классам.

```text
есть hard-risk rule                         -> профильная очередь + оператор
router confidence < 0.70 или модель OOD    -> общая triage-очередь
route уверенный, но ответ/RAG не уверены    -> маршрут сохраняется, ответ вручную
ответ уверенный, но категория не allowlist -> черновик оператору
все проверки пройдены                      -> автоответ
```

Модель может отказаться (`abstain`). Это нормальный результат: цена лишней
ручной проверки ниже цены опасного ответа или неверного автозакрытия.
